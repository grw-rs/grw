A worked example, end to end

One graph, the whole loop.

A microservice fleet: services are nodes, calls are directed edges, latencies are edge values. A deploy sneaks in a circular dependency — patterns find it, modify! removes it, navigation proves the deploy still paid off. Every snippet below is extracted from tests/site_story.rs and runs in the test suite.

act 1 graph! — build the fleet
type ER = grw::edge::Dir<u32>;  // latency in ms

grw::graph![<&'static str, ER>;
    N(0).val("gateway") & E().val(2) >> N(1).val("auth"),
    n(0) & E().val(3) >> N(2).val("orders"),
    n(1) & E().val(9) >> N(3).val("db"),
    n(2) & E().val(4) >> N(4).val("billing"),
    n(2) & E().val(12) >> n(3),
    n(4) & E().val(1) >> n(3)
].unwrap()
act 2 modify! — the deploy, one atomic transaction
// add a cache between orders and db — plus an
// accidental callback edge billing → orders
grw::modify!(g, [
    X(2) & E().val(1) >> N(0).val("cache"),
    n(0) & E().val(2) >> x(3),
    x(4) & E().val(5) >> x(2)
]).unwrap();
// applies as one unit — or not at all

act 3 · search!

Ask the graph questions.

Each query is drawn in pattern space: amber nodes are what you bind, rose is what must not exist, dashes are variable-length paths.

// fan-out: services calling ≥ 2 others
search![&g, get(Mono) {
    N(0) >> N(1),
    n(0) >> N(2)
}]
// entry points: nobody calls them
search![&g, get(Mono) {
    !N(1) >> N(0)
}]
// → only the gateway
// redundant shortcut: chain + direct edge
search![&g, get(Mono) {
    N(0) >> N(1),
    n(1) >> N(2),
    n(0) >> n(2)
}]  // orders → billing → db, plus orders → db
// circular dependencies
search![&g,
    get(Homo) { N(0), N(1) },
    get(Mono) { n(0) >> ..n(1).dfs().len(1..) }
]  // Homo lets 0 and 1 collapse onto one node
consume the Match — addressed by your own numbering
for m in &session {
    let caller = m[0];            // Index: absence = bug
    let callee = m.get(1).unwrap(); // Option: tolerant

    let tm = session.translate(&m); // ids → values
    let (_, name) = tm.node(LocalId(0)).unwrap();
}

// cycles: filter on the mapping itself,
// and read the concrete path behind the edge
session.iter()
    .filter(|m| m[0] == m[1] && !m.path(0).is_empty())
    .count()  // 1 — billing → orders closed a loop
act 4 modify! — remove the edge, prove it's gone
grw::modify!(g, [x(4) & !e() >> x(2)]).unwrap();

// re-run the same cycle pattern:
session.iter()
    .filter(|m| m[0] == m[1] && !m.path(0).is_empty())
    .count()  // 0 — fleet is acyclic again
act 5 navigate — the deploy still paid off
let cfg = Config::new(())
    .navigate(Dijkstra::weighted(|ms: &u32| *ms as f64));

let (cost, path) = g
    .path_navigate(N(0), N(3), outgoing, cfg, &constraint)
    .next()
    .unwrap();

// before the deploy:  gw → orders → billing → db = 8 ms
// after:              gw → orders → cache → db  = 6 ms

Variable-length paths

A path is just ..

Prefix a pattern node with .. and the edge becomes a variable-length path: traversal, length bounds, or cost-ordered navigation — all lazy, one path per next(). Full chapter in the book →

..n(1).dfs()                                              // deepest-first simple paths
..n(1).bfs().len(3..10)                                   // shortest-first, 3–9 edges
..n(1).navigate(Dijkstra::counted())                      // cheapest by hop count
..n(1).navigate(Dijkstra::weighted(|ev: &EV| ev.cost))    // cheapest by edge weight
..n(1).navigate(AStar::new(|ev| ev.cost, |n| h(n))).all()  // every simple path, cost-ordered
..n(1).dfs().guard(|p| !p.contains(N(2)))                 // prune paths mid-walk
..n(1).drive(|n| Some(Explore::One(0)))                   // steer expansion per depth

Mutable vs versioned.

GRW ships two stores behind one read trait: MGraph mutates in place; VGraph is persistent — every modify returns a new version, old versions stay live, structure is shared. The price is paid on writes and raw scans; through the search index the two are indistinguishable — and keeping a version costs 20 ns, flat, at any size. 1M nodes / 2M edges, median of 3:

Graph model

One type, three kinds of edge.

A Graph<NV, ER> is parameterized by its node-value type and its edge relation. The relation picks which operators are legal and how many edges can sit between any two nodes.

^

edge::Undir<EV>

One undirected edge between two nodes. Slot: UND.

>>  <<

edge::Dir<EV>

Up to two directed edges — one incoming, one outgoing. Slots: SRC, TGT.

^ >> <<

edge::Anydir<EV>

All three at once — undirected plus both directions. Slots: UND, SRC, TGT.

The theory underneath

Six morphisms, one lattice.

Every get and ban above names one of these. A morphism maps pattern nodes to target nodes while preserving edges; three independent axes decide how strict that mapping is, and they collapse into six named morphisms, ordered from exact to anything-goes. Chapter →

injective · one-to-one surjective · covers all induced · exact neighborhood
IsoExact match — same shape, same size, same edges.
SubIsoFind this exact shape inside the target.
EpiMonoBijection, but extra edges between matched nodes are OK.
MonoEach pattern node gets a unique target; extra edges OK.
EpiMust cover all target nodes; can collapse pattern nodes.
HomoAnything goes — just preserve edges.

Going up the lattice adds constraints; going down relaxes them. The meet() of two morphisms is the most relaxed one that still satisfies both. Clusters with different morphisms compose under one rule — two nodes may share a target iff they are not both injective — with the nuances drawn out in Mixing Clusters & Morphisms.
